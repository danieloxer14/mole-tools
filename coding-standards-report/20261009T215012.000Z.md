## Findings

### Enabled rules

#### `exhaustive-checks` — MUST — fixed

- **Location:** `src/features/review/ui/components/MrHeader.tsx:50-56`
- **Structure:** module scope (`PROVIDER_PRESENTATION`)
- **Why:** `Record<GitHostProvider, ...>` requires a presentation entry for every provider and centralizes title separator and external-link label selection.
- **Before**
  ```tsx
  provider === "github" ? "#" : "!"
  label={mr.provider === "github" ? "Open in GitHub" : "Open in GitLab"}
  ```
- **After**
  ```tsx
  const PROVIDER_PRESENTATION: Record<
  	GitHostProvider,
  	{ iidSeparator: string; externalLinkLabel: string }
  > = {
  	github: { iidSeparator: "#", externalLinkLabel: "Open in GitHub" },
  	gitlab: { iidSeparator: "!", externalLinkLabel: "Open in GitLab" },
  };
  ```

#### `local-helper-functions` — SHOULD — fixed

- **Location:** `src/features/review/ui/components/MrHeader.tsx:50-56`
- **Structure:** module scope (`PROVIDER_PRESENTATION`)
- **Why:** One provider presentation map keeps the repeated separator and link-label decisions consistent across header and tab titles and the external link.
- **Before**
  ```tsx
  provider === "github" ? "#" : "!"
  provider === "github" ? "Open in GitHub" : "Open in GitLab"
  ```
- **After**
  ```tsx
  const PROVIDER_PRESENTATION: Record<
  	GitHostProvider,
  	{ iidSeparator: string; externalLinkLabel: string }
  > = {
  	github: { iidSeparator: "#", externalLinkLabel: "Open in GitHub" },
  	gitlab: { iidSeparator: "!", externalLinkLabel: "Open in GitLab" },
  };
  ```

#### `always-use-braces` — MUST — fixed

- **Location:** `src/features/review/ui/main.tsx:864-874`
- **Structure:** `useEffect` document-title guard
- **Why:** The updated guard uses braces around its early-return body.
- **Before**

### Proposed rules (report-only)

#### `parameterized-tests` — SHOULD — match

- **Location:** `src/features/review/ui/components/MrHeader.test.tsx:622-630`
- **Structure:** `test("covers pure display helpers")`
- **Why:** Provider-specific title assertions exercise the same formatting behavior with different inputs; parameterized cases could identify the failing provider case directly.
- **Before**
  ```tsx
  expect(headerTitle("", 42, "gitlab")).toBe("!42");
  expect(headerTitle("", 42, "github")).toBe("#42");
  expect(tabTitle("group/r", 42, "github")).toBe("r#42");
  ```
- **After** (suggestion only)
  ```tsx
  test.each([
  	{ provider: "gitlab", expected: "!42" },
  	{ provider: "github", expected: "#42" },
  ])("uses $provider issue-number formatting", ({ provider, expected }) => {
  	expect(headerTitle("", 42, provider)).toBe(expected);
  });
  ```

#### `single-conceptual-tests` — SHOULD — match

- **Location:** `src/features/review/ui/components/MrHeader.test.tsx:622-630`
- **Structure:** `test("covers pure display helpers")`
- **Why:** The test groups title formatting with unrelated SHA, approval-tooltip, and changed-file helper assertions; separate tests could localize failures.
- **Before**
  ```tsx
  test("covers pure display helpers", () => {
  	expect(headerTitle("", 42, "github")).toBe("#42");
  	expect(shaButtonLabel(base.headSha, false)).toBe("12345678");
  	expect(filesChangedLabel(3)).toBe("3 files changed");
  });
  ```
- **After** (suggestion only)
  ```tsx
  test("formats GitHub pull request titles", () => {
  	expect(headerTitle("", 42, "github")).toBe("#42");
  });
  ```
