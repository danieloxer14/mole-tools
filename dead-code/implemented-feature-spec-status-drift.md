## Why this is safe to change
These are specifications and generated planning tickets, not runtime inputs. Updating status, checking only verified criteria, or explicitly archiving completed plans cannot change command parsing, prompt construction, worktree behavior, or help output. The `--base-dir` versus `--baseDir` mismatch is a documentation contract issue; preserve any intentional compatibility alias only after checking the CLI compatibility boundary rather than changing production parsing here.

## Proposed change
1. Mark the `--auto` and `--context` specs/tickets implemented only where each acceptance criterion has current source and focused-test evidence; otherwise archive the generated tickets as completed/superseded plans with the verification boundary stated.
2. Mark the worktree-prune spec/plan as implemented or historical, replace future-stage language with the current flow, and reconcile the documented flag spelling with the actual CLI contract without changing runtime behavior.
3. Mark the help implementation plan's completed phases and replace `Implement Phase 1` with a maintained-status note; repair its source-document links as part of the separate cross-link cleanup ticket.
4. Keep unresolved product decisions or missing focused coverage explicitly open rather than checking them merely because code exists.
